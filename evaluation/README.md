# 冻结质量样本 v1

15 个手工编写的合成样本；名字、网址、数字均为虚构，并非真实搜索记录。
依据 wiki 的 rs-p0-p1-roadmap、rs-evidence-pipeline 和 rs-citation-validation：
固定证据比较综合结果，尤其检查冲突、缺失、跑题、注入及引用支持完整性。

输入冻结在采集/选择之后。此版本只评估综合与解析，不评价搜索召回、清洗或
Jev 阈值；这些阶段需要另建固定的候选来源及选择标注，不能从这里推断优化效果。
重放沿用当前生产提示词和来源 ID 协议：Python 标注来源编号，模型返回编号和摘录，
生产解析器还原公开的来源 URL。没有引入评估服务或额外模型裁判。
旧 URL 输出协议的报告仍保留为历史记录，不能直接当作当前协议的测试结果。

从仓库根目录执行：

```bash
# 默认离线，只检查样本结构和来源约定
.venv/bin/python -m evaluation.run

# 显式运行真实 LLM：15 次串行综合调用，会产生 API 费用
# 使用现有 .env；保存目录须已存在，报告文件不能已存在
.venv/bin/python -m evaluation.run --live --output /tmp/rs-quality-baseline.json
```

每个样本一次调用，不修复、不补跑；temperature=0，关闭 SDK 重试。
报告保留原始输出、解析结果、机械校验错误、耗时、模型、输出格式、代码提交及
样本/提示词哈希。不会记录密钥或 provider 异常正文；不采集 token 或声称货币成本。
调用失败保留在全部 15 个样本的分母内。报告不会自动写入仓库。

人工检查每个样本的 `must_cover` / `must_avoid`，填写报告的 `review`：

| 字段 | 0 | 1 | 2 |
|---|---|---|---|
| coverage | 未回答或漏主要事实 | 部分覆盖 | 覆盖要求且无明显冗余 |
| support | 有无支持或矛盾主张 | 部分支持，含跨来源引用缺口 | 所有实质主张均有支持 |
| caveats | 隐瞒限制或编造确定性 | 限制不完整 | 正确表达缺失、冲突与适用范围 |

`support` 检查所有要点、key_details、caveats；跨来源比较应引用双方证据。
空证据时检查是否诚实说明无法回答，不要求引用。
无效输出不填语义分，仍计为失败。报告机械通过率、三个维度的逐例分数和失败 ID，
不把机械通过率当质量分，也不只比较有效输出后宣布整体改进。

先跑并人工审阅一份 baseline，再仅修改一个变量、用相同模型和配置运行 candidate。
小样本结果用于定位回归；单次差异不构成稳定提升证据。需要判断稳定性时，对两臂
等次数重复，保留每次失败，不挑最好的一次。温度为零仍可能波动。
模型端的 thinking 等选项须保持一致；当前脚本不覆盖 provider 专属设置。

冻结后不为迎合某个输出修改样本。修正事实或审阅标准时提升 `version`，保留 git diff，
重新跑 baseline。新增真实故障样本需去除敏感信息并注明来源。
